扩展 FFT 计划空间：2026-10-31 中期分析

一、目标与结论范围

本报告分析一次受预算限制的候选搜索，问题是：在固定的一维 FFT 工作负载上，允许改变有序 radix 分解、统一逻辑寄存器数 R 和 grouped batch G 后，能发现哪些相对于 VkFFT 原始默认计划更快、且经过数值检查的计划；这些发现与历史固定首尾的结构空间有何关系。数据来自同一轮重新准入的云端 RTX 4090，GPU UUID 为 GPU-4c8e177a-5a3a-3e0f-61b7-fb666002e0ec。GPU 重新分配后重新测量默认与候选，不复用其他设备时延。

28 个预定负载都完成了默认观测及至少一个非默认候选筛选。在 353 个完成筛选的候选中，325 个是非身份候选；其中 31/325（9.54%）筛选时快于默认，12/325（3.69%）筛选时至少快 2%。按负载而非候选计，13/28（46.43%）的最佳非默认筛选点快于默认，8/28（28.57%）筛选点至少快 2%。13 个胜者进入两个独立确认 session，8 个在两次 session 均达到预定实用标准；其余 5 个未达标准。未有筛选胜者的 15 个负载按默认回退。

两个 session 的等权几何平均比值中，最强确认案例 N=128、batch=16 的候选/默认时延为 0.832423，即延迟下降 16.76%，对应加速约 1.2013 倍。28 个负载等权、达标才选候选否则默认的事后回退估计，几何平均加速 1.02295 倍，算术平均延迟下降 2.152%。这是针对这 28 个已知负载、已筛选候选和观测结果的策略估计，不能当成未见负载上的预测或已部署收益。

二、工作负载、域和分母

负载矩阵是 N={128,256,512,1024,2048,4096,8192} 与 batch={1,16,256,4096} 的笛卡尔积，共 28 项。范围限定为 FP32、一维、复数到复数、正向、out-of-place、单 upload、registerBoost=1，不包括 Rader/Bluestein。候选是乘积为 N 的 {2,4,8,16,32} 有序 radix 分解，统一 R∈{2,4,8,16,32,64,128,256}，G 为 batch 的 2 次幂约数；R>N 或最大 radix>R 静态拒绝。候选仅是请求，不能从枚举数推导设备可运行数；scheduler、编译资源、实际计划、数值与执行还须通过检查。

28 个 manifest 的数学请求共 1,592,864 个，其中静态拒绝 502,684 个，静态支持 1,090,180 个。静态支持中未选择 1,086,596 个，选中 3,584 个；选中中完成筛选 353、scheduler 拒绝 155、资源拒绝 0、部分完成 1、未启动 3,075。部分和未启动均不是性能观测。预算在一次 timing 工作启动前耗尽；不得把未测点当作失败或慢点。

统一 R≤64 子域完成 276/选中 2,346，静态支持 693,672；R=128 或 256 子域完成 77/选中 1,238，静态支持 396,508。后者的已筛选最优比值为 2.56618，仍慢于默认。两子域的分层选择和完成数不均，不能解释为等预算优势；R≤64 是当前原型的一个子域，并非历史旧空间。

全部候选数 353 中 43/353（12.18%）筛选时小于 1、12/353（3.40%）不大于 0.98；这包含 28 个身份重放。非身份分母 325 是研究非默认候选的更合适口径。分层选择过采样某些 stage 数、R 和 G，以上比例不是整个可行域随机样本的成功概率。

三、正确性、计时和确认

原始与实验默认计划做 identity 比较及重放，绑定同一 GPU、二进制和源码证据。每个非拒绝候选须通过实际计划与资源检查，针对 zero、impulse、constant、quarter-tone、random 五种输入及种子 42、53、71 的数值验证；检查输入不变、输出覆盖、CPU 参考、非有限值和结果完整性。实验失败或 scheduler 拒绝不作为时延点。

筛选每候选使用 3 轮候选与原始默认配对，轮次执行顺序按固定种子随机交替；每轮采用图执行样本的中位时延，报告 3 个候选/默认比值的中位数。运行包括预热，重复地址和 CUDA graph；不代表冷缓存、端到端初始化或业务总时延。两个后续独立 session 对 13 个筛选胜者各做 10 轮配对。每个 session 的预定实用判据是几何平均延迟下降至少 2%，且该 session 的配对 log-t 95% 区间上界小于 1；必须两次都满足。两个已选慢点作为负对照，两次 session 均显示默认更快，不计入胜者。

区间只描述 session 内配对变动，依赖配对块独立等假设，不修正从筛选点选胜者及多重比较，也不保证设备间泛化。guard 审计通过，但周期采样不能排除采样间隔内干扰。两个 session 的独立是独立 session 和测量，不等于独立设备。

五、历史旧空间和扩展点

历史 joint 枚举以同设备默认计划为基准：首尾 radix 固定，内部由 {2,4,8,16,32} 有序分解，原计划至多两级时只能保留原序列；G 是 batch 的 2 次幂约数且不超过 1024，继承默认 FFT 线程维度及 scheduler 的每 radix 寄存器表与最小/最大 envelope，并经线程和共享内存预筛。候选仍需 scheduler、资源和正确性验证。生成规则见 test/plan_selection_study/direct_candidates/enumerate_joint.py，保守结构分类见 expanded_search/audit_old_space.py。

本轮 353 个完成点中，51 属旧结构子集（含 28 个身份点、23 个非身份点），302 在旧结构域外，0 个不可比。23 个旧子集非身份点中 8 个筛选时快于默认、4 个至少快 2%；302 个旧域外点中分别有 23 和 8 个。两次确认均达实用标准的 8 个胜者中，5 个为旧域外、3 个为旧结构子集。结构子集判定还要求寄存器表、线程数和实际 localSize 与旧规则一致，但不证明旧实现的源码、编译选项或完整运行状态等价。

这只是同一次分层样本的回溯分类。旧结构点和域外点数量、选择规则及测量成本不等，未独立复现旧搜索，因此不能声称新搜索以相同预算击败旧搜索，也不能把组内最优称作完整旧域或新域最优。要回答搜索效率，需同设备上预先冻结旧、新各自合法域与采样方法，按相同候选数或墙钟预算独立重复，并对获胜点采用相同确认协议。

六、耦合与 LUT / coalesced 小实验

筛选中固定 R 和 G、改变 radix 的可比较组有 77 组/229 对；固定 radix 和 G、改变 R 有 44 组/68 对；固定 radix 和 R、改变 G 有 18 组/29 对。这些比较反映整个计划的共同变化，不是单参数因果效应。例如 N=4096、batch=16、radix=[16,16,16]、R=16，G=1 与 G=2 的筛选比值分别为 1.00005 和 2.47705；同时 localSize 从 [256,1,1] 变为 [2,256,1]、动态共享内存从 34,816 变为 65,536 字节，源码哈希也变化。N=512、batch=1、radix=[2,2,2,2,2,2,2,2,2]、G=1 时，R=4 与 R=256 的筛选比值为 1.17494 和 115.54214；localSize 分别为 [128,1,1] 与 [2,1,1]，编译诊断 local bytes 为 0 与 4,968。共变不能单独证明哪一项导致性能差异。

另对 N=128、batch=16 的两个固定 radix/R/G 计划，测试 LUT 请求 {-1,0,1}（分别为关闭、自动、开启）与 coalesced 请求 {0,16,32,64,128} 的 30 种组合，30/30 完成，均为三轮筛选，分母为原始无旋钮默认。

计划 [8,8,2]/R8/G8 的 LUT 关闭、访存自动组合 (-1,0) 比值为 1.000000；最佳 (-1,32) 为 0.9996256，两个独立对默认的筛选中位数相除为 0.9996256，约 0.0374% 差异；最慢 LUT=1、coalesced=0/32/64 为 1.180867，较该计划上述参考组合约慢 18.09%。计划 [8,16]/R16/G1 的 LUT 关闭、访存自动组合 (-1,0) 为 0.83258597，最佳 (-1,16) 为 0.83257431，相除为 0.9999860，约 0.0014% 差异；最慢 (1,32) 为 0.93759347，相除约 1.12612，即慢 12.61%。两个最小差异不是直接候选对上述参考组合的配对结果，也未独立确认，不能主张有意义的旋钮增益。

两计划的 coalesced=0 均解析为 32，LUT=-1 的实际 LUT 均为 0。每个固定计划的 15 个请求仅有两种不同的 canonical descriptor、source SHA-256、source bytes 和 compiler input 四元组：LUT=-1 或 0 的十项同一组，LUT=1 的五项同一组；16/64/128 请求的 resolved coalesced 数值仍不同，所以这只证明上述记录项相同，不证明所有运行状态相同。结论限于这两个计划和一个负载。

七、成本与限制

搜索账本从首条开始至末条完成或拒绝的观测区间为 10,188.726 秒（约 2.83 小时）：有记录 work 10,115.025 秒，间隙 73.702 秒。work 中 validation 4,910.955 秒、timing 4,593.636 秒、describe 264.316 秒、拒绝后控制 192.711 秒、identity 72.163 秒、calibration 81.243 秒。work 包含子进程、JIT、guard、记录和调度，不能解释为纯编译或纯内核时间；账本区间不包括全部构建、准备、后处理和确认，因此不是整个研究总墙钟，也不能直接推算线上调优摊销。

尚未覆盖非 uniform 的 per-radix 寄存器表、非 2 次幂混合 radix、boost>1、多 upload、每个同 radix stage 独立寄存器、其他精度或方向、不同布局和冷缓存。放宽白名单不足以正确支持这些路径，必须在依赖计划生成前注入并重新计算布局、资源与代码生成，再单独数值准入。推荐优先完成预注册的旧/新等预算多次比较和独立设备复现；再以非 uniform per-radix 寄存器作为受控扩展，单独评估 2/3/5-smooth 单 upload 工作负载；boost 与多 upload 应建立独立计划契约和端到端验证。以上均为建议，不是已测结果。GPU0 的新增确认仍在运行，结果待完成和审计，本报告不预支其结论。
