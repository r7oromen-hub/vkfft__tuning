# 扩展搜索独立审计契约

本文件描述审计所需的证据，不表示搜索、确认或跨会话复核已经完成。准入验证与核心搜索分协议、分预算报告，不能作为核心搜索的性能发现。审计器以实际版本化 schema 与原始日志为准，缺字段或关联不完整时标记“不足以验证”，不推测为成功。

## 预注册与覆盖

核心协议以 [study_protocol.json](study_protocol.json) 为准，预注册 7 个长度 × 4 个 batch 共 28 个工作负载，记录方向、精度、布局、设备、缓存模式、代码版本、候选生成器版本及所有可变搜索规则。逐工作负载保存可复现的有序数学分解全集或无损生成规则、原型支持条件、预筛原因、候选描述与唯一 ID、分层抽样算法、随机种子及抽样前序号。候选 ID 基于完整请求和工作负载，并保存原始请求，不能用短哈希作为唯一身份。注册每组选择的非默认请求：**最多 64 个，失败和重复均占名额，默认不计**。重复请求不因去重减少请求计数；允许另列实际不同源码与状态数。若候选空间太大，使用可复现规则和聚合计数替代物化，记录确定性枚举次序与结果摘要哈希。

独立分类并互相核对：数学空间、原型支持空间、预筛拒绝（附原因）、抽中但未开始、已开始、执行失败/数值错误/资源拒绝、执行完成并满足验证、结构重复、因预算/干扰/中断未执行。不能将未抽中、未覆盖或预筛拒绝描述为“测试未通过”，也不能把执行失败和数值失败当作慢候选。记录实际统计分母；来源未知的状态视为审计失败。

## 运行证据与 GPU 守卫

每个命令关联唯一 `run_id`、候选 ID、session、阶段、轮次、输入模式及 seed，记录 argv、显式环境覆盖、控制二进制与生成器/头文件/代码哈希、编译选项、GPU UUID、进程身份、UTC 与单调时钟、退出码以及 stdout/stderr 或内容哈希和存储路径。随机顺序在计划时种子化并保留实际执行顺序。运行行须能关联 guard 的注册、启动、结束、前后边界及周期采样事件；污染、意外中断、缺失守卫或采样覆盖不足不计入干净性能比较。采样不能排除采样间隙短暂干扰，应标明局限。每个结果须可从记录中核验请求与实际 radix、逻辑寄存器、group 和推导的布局一致，核验编译后函数/设备的线程和共享内存限制、完整输出的数值误差、输入未改写和所用阈值。相同源码不自动意味着运行时计划相同，去重应组合必要计划状态。

身份对照使用相同实际结构、编译选项和计划状态与原始头文件源码/资源证据比较。若当前候选接口无法表示默认全部结构，必须标记“不可表示”，不得仅凭 radix 相同判定 identity；默认控制仍独立执行。

## 预算、确认与统计

协议将设备预留墙钟总限设为 28800 秒，分为准入 5400、搜索 12600、确认 7200、扩展 3600 秒；包含构建、验证、guard 空闲和计时，阶段相互独立。记录每阶段可启动的截止时间以及保留的确认时间；单调时钟账本须可跨 controller 重启延续，checkpoint 保存已用时、剩余时、下个工作负载、现存 PID/任务和完整性。任何预算耗尽、信号、异常或超时均保存 terminal reason 及全部未启动项，后续恢复不得重置已用时。启动前按历史上界尽可能预留时间，到期停止启动新任务；允许已启动任务完成，超出部分单独报告，不得事后改写预算。guard 暂停、失败、编译和必要同步都需计入相应预算，不可只计 CUDA event 时间。

筛选使用成对、随机区组；保存每轮原始默认和候选的耗时，而非仅保存摘要。被选中的正向候选须至少在独立进程中和**原始头文件默认**完成 10 轮随机配对确认，保存每一轮 seed、顺序、计时样本及守卫证据；正向结论再在第二个独立会话复核，记录两会话设备与软件环境。同一会话的 10 轮不视为跨会话或跨设备复现。用逐轮 `log(candidate/default)` 计算几何均值与 t 区间，每会话分别报告；按协议的 2% 实用降时门槛及区间上界小于 1.0 判别，明确该区间没有控制筛选和多重比较偏差。报告完整候选与筛选分布，区间依赖区组独立性等假设。失败确认、没有第二会话、预算中断及缺失原始默认均明确列为未确认，不可宣称加速。搜索策略输出必须允许默认回退，不能把选出较慢的非默认候选当作实际输出。

## 审计输出

审计生成机器可读的分组/分类计数、缺失和冲突证据、预算余额、失败原因、干扰与确认状态，并以可读报告标记证据等级。任何 assertions 或缺失输入产生非零退出码；应支持保留部分结果但不得将“不足以验证”的工作负载标为通过。审计程序应有构造性离线测试，至少覆盖超 64、漏 manifest 行、重复请求、错误身份、hash/guard 不一致、缺轮、数值错误、预算跨重启与缺第二会话。
