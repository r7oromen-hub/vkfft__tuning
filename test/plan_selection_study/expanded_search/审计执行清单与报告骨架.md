# 审计执行清单与报告骨架

此文件用于后续填报，不包含尚未取得的核心搜索、两会话确认或超 L2 测量结论。实验运行、审计和设备等待均须遵守[固定搜索协议](search_protocol_v2.json)及[证据契约](audit_contract.md)。本地审查版本的文件指纹见[审核版本 SHA-256](审核版本_sha256.json)；实际运行必须以对应远端冻结 checkpoint 和原始二进制哈希核对，不应将本地快照自动当作远端版本。

## 静态自检

在 `test/plan_selection_study/expanded_search` 下执行：

```text
python -m unittest discover -v
ctest --test-dir cpu_build --output-on-failure
ctest --test-dir rotation_cpu_build --output-on-failure
```

本地本次独立复跑 Python 66 项、生成器 CPU CTest 3 项、rotation CPU CTest 2 项通过。测试中的一次 `argparse` 拒绝是用例主动构造的预期异常。Linux 设备进程锁、CUDA 编译、graph 节点地址及真正的多地址运行不由这些 Windows CPU 测试证明；在设备数据到达后必须重新验证。若源码或测试变动，重新测试并另行记录哈希。

首次受守卫准入曾因 `axisSwapped` 初始化后复位导致身份检查误判；[独立事故审计](results_20261030/准入中止独立审计.md)保留原始证据。修复版的[独立准入审计](results_20261030/admission_v2_independent_audit.json)已核对 8 个工作负载、9 个完成数值的候选及 1 个拒绝请求；[准入 gate](results_20261030/admission_v2_gate.json)仅授权协议范围内的核心实验，不代表所有 radix 或 layout 都已通过。

## 数据到达后的独立审计顺序

1. 搜索完全结束后，保存独立不可变的 rows、guard、incidents、所有 manifest 和 search budget snapshot。核验各文件 SHA、所有运行守卫及原始/扩展二进制哈希；中途异步快照不能作为完整 gate。
2. 在计入确认阶段预算且持设备锁的审计环境中运行 `audit_runner.py --kind screen`；它调用 `make_screen_gate.py`，分别复核 `audit_search.py`、`audit_space.py`、`audit_screen.py`、`audit_guard.py`、`audit_budget.py`。传入全部先前准入 rows，以逐运行对账。`pass` 只表示实际执行与完整候选的证据一致，未抽中、被拒绝、预算未启动与部分轮次必须分别列出。
3. 用 `audit_old_space.py <search-rows> --manifests-dir <manifest目录>` 复原旧首尾、寄存器表/包络、FFT 线程维、group 与 block 规则，报告抽中的旧结构子集和扩展独有点。旧结构匹配不是源码/编译选项/完整运行状态等价证明；如没有公平同预算对照，明确写未覆盖，并把[前期旧实验](../direct_candidates/results/joint_newhost_20261030/调优空间敏感度与耦合研究.md)另列。
4. 用绑定 screen gate 的固定计划，先按筛选耗时比顺序确认筛选更快的方案，再最多确认两个默认更快的对照。每项与原始默认随机配对 10 轮；不足 10 轮列为未确认。对首会话生成独立预算快照，运行 `audit_runner.py --kind first` 产生 first-session gate。第二会话仅选择首会话完整、角色为 `screen_faster` 且几何比小于 1 的候选，优先满足实用门槛和区间条件者。
5. 对第二会话运行 `audit_confirmation.py` 并生成不可变预算快照；`make_two_session_gate.py` 重新核对两份原始记录、守卫、审计、预算和计划。只有两个不同会话各自的候选/原始默认配对几何耗时比均不大于 0.98、且各自 95% t 区间上界小于 1 的筛选正向候选，才能标为符合预注册规则。区间仅限该会话，未校正筛选和多重比较，也不能证明跨 GPU 泛化。
6. 若存在上述确认候选且 extension 阶段预算足够，再以 two-session gate 在独立二进制和原始头依赖检查下尝试[超 L2 轮换](ROTATION.md)。图参数不可读、资源或预算不足均记未覆盖；工作集大于 L2 不证明每次 miss 或冷缓存。超 L2 结果本身需单独审计，不得借用热缓存结果作替代。

## 结果报告骨架（待填）

### 已验证事实

- 搜索协议与设备：**待最终日志**；报告 GPU、驱动、CUDA/NVRTC、实验模式和缓存条件。
- 数学分解、原型静态支持、预筛拒绝、抽中、实际启动、数值通过、完整筛选、重复、部分及未执行：**待审计计数**。每 workload 最多 64 个非默认筛选请求，失败/重复也占额；默认不计。
- 默认回退与筛选分布：**待审计统计**。先给全部工作负载及分母，报告默认选择次数、最坏回退和未确认数量，不只展示赢家。
- 旧空间/扩展结构范围：**待完整 manifest 和源码核对**。若无法满足共同预算，不报告“新方法优于旧搜索”。
- 独立确认：**待一、二会话原始配对与 gate**。逐工作负载给每会话几何比、区间、完整轮数；分开列正向、默认更快的对照与部分/未测。
- 超 L2 循环：**未验证**，除非实际 CUDA 构建、受守卫运行、所有 slot 输入/输出和已冻结 harness 记录的图地址检查均经离线审计。离线审计不能独立重读原始 CUDA graph，也不证明冷缓存或 cache miss。
- 混合因子长度和多 upload：**本轮未实施、未测量**。[限制、源码依赖与后续准入路径](混合因子与多上传未覆盖与后续路径.md)单独列出；超 L2 rotation 不改变该覆盖状态。
- 总预算、各阶段实际墙钟、in-flight、超时/超额和设备干扰：**待冻结账本与守卫审计**。异常与采样空隙局限须保留。

### 解释边界

分层按 stage、多重集、静态预测线程维和 group 轮转，不是对整个结构空间的均匀采样，可能相对过度抽取极端阶段数或寄存器值。固定本轮抽样，不因中途性能改点。默认是强基线；没有新收益仍可作为本范围覆盖与回退证据，不能推断全局最优。

参照[原始文献与创新边界](../direct_candidates/搜索空间扩展与阶段决策.md)：GPU FFT 的 radix/分组/资源剪枝及探针、FFT 结构成本模型、分层程序搜索与学习排序都有先例。本轮没有训练模型；只有在独立确认收益、覆盖和总成本支持的条件下，才考虑按长度族与整架构留出、无泄漏的小预算模型对比。
